## Findings and issue coverage

### AUDIT-001 — Filesystem corpus lock binding is stale

**Classification:** confirmed defect. **Severity:** medium. **Confidence:** high. **Status:** confirmed. **Coverage:** focused issue proposed. **Area:** validation/provenance. **Effort:** small. **Impact:** medium. **Why it matters:** PR and scheduled filesystem corpus checks refuse current main, so the intended current corpus executions do not occur.

`scripts/filesystem-corpus.py::generated_index` binds `Cargo.lock`. The committed index contains SHA-256 `4e1f382de4f48c85705713b61d25890de6865fa517153d6afcd0b3cc1ac42306`; the current lockfile hashes to `1c77b5517da29ef329ee2199dd4c11f644f30b9faac3630c1338c5d807a9ea3e`. An in-memory structural comparison finds that field alone differs. Generator/catalog/recipe/expected/proof/payload entries are unchanged. Both PR hosts and the scheduled host show the same refusal.

**Recommendation:** a narrow reviewed lock-binding reconciliation under #65, with an explicit dependency-update path. Preserve the current fail-closed drift detection, exact dependency identity, read-only CI and reviewed fixture proofs. Do not blindly regenerate or remove lock identity merely to clear the check.

**Acceptance:** index checks pass on the reviewed unchanged checkout; bounded PR/scheduled execution is recorded independently; a lock-only change has a documented review path while recipe/proof drift still refuses. No native or physical-drive guarantee follows from index equality. **Dependencies/risks:** no missing product prerequisite; reconcile any chosen dependency PR first and refresh evidence if its lockfile changes. New focused issue: **https://github.com/egohygiene/optiflow/issues/136**; umbrella #65 remains open.

### AUDIT-002 — Candidate-artifact unit fixtures fail on macOS temporary paths

**Classification:** confirmed defect. **Severity:** medium. **Confidence:** high. **Confidence detail:** the hosted failure and fixture cause are observed; native repair remains unverified. **Status:** confirmed. **Coverage:** focused issue proposed. **Area:** platform validation. **Effort:** small. **Impact:** medium. **Why it matters:** the supported macOS validation job fails before completing its remaining checks.

The exact-source [macOS Validate job](https://github.com/egohygiene/optiflow/actions/runs/39167986165/job/117794891823) reports eight `candidate_artifact::tests` failures with `unsafe directory component` and `Not a directory (os error 20)`. Ordinary fixture `private_root()` uses `tempfile::tempdir()`; macOS exposes its temporary path through `/var`, a symlink. The production directory walk intentionally opens all components using `DIRECTORY | NOFOLLOW`. The existing `tests/png_production.rs::SyntheticRun::new` already creates fixtures below a canonicalized system temporary root for exactly this reason.

**Recommendation:** use a trusted real temporary root for ordinary candidate-artifact fixtures and preserve explicit adversarial symlink cases. Do not weaken production no-follow/private-root checks or infer a production bypass. **Acceptance:** all eight affected cases execute and pass on native macOS plus focused Linux regressions; exact membership/evidence binding/refusal/cleanup assertions remain intact. **Dependencies/risks:** no missing product capability prerequisite; a native host is required for repair verification. Do not duplicate #111's transaction port or treat this repair as APFS qualification. New focused issue: **https://github.com/egohygiene/optiflow/issues/137**, under #65.
