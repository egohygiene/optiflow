# ADR-0003 — Keep optional evidence explanations separate from source authority

- **Status:** Proposed; source inclusion/merge is not ratification.
- **Date:** 2026-11-10
- **Issue:** #133

Normalize explicitly pinned immutable report/plan bytes into bounded count facts
and opaque record references. Reuse SDK v1 ReportProvider for supplied fake
candidates and fingerprinted advisory contributions; no new SDK/router, Flow
dependency, raw-source capability or secret-bearing generic request is justified.

Host-render exact selected recorded facts. Check citation membership separately
from suggestion meaning. Mark semantic grounding, current collection freshness,
physical reclamation and actual model execution as unverified. A sidecar cannot
mutate or approve a plan or establish source eligibility/deletion authority.

Existing schema/artifact-set/SDK/lock/result owners remain authoritative. Future
real runtime/profile adoption, narrow credential handoff and native usefulness
need explicit follow-up; disabled/missing candidate is ordinary optional behavior.
Qualification is deferred to flow #88 last. Prior ADR dispositions are unchanged.

2026-11-10 additive source checkpoint: explicit pinned-record CLI and an optional
local-process profile handoff reuse SDK v1 ProcessExtensionClient/ReportProvider.
The operator lock owns exact executable/configuration/effect identity. The host
accepts only a normalized candidate report and grants no source authority.
Inherited environment/secret input and remote fallback are absent. Trusted
process locality/model identity remain declarations rather than sandbox proof.
This addition does not ratify this ADR or establish runtime qualification.
