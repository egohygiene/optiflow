# ADR-0005: Require current native validation at video replacement

Status: Proposed, 2026-11-10. Source inclusion is not ratification.

Reuse the existing guarded video provider for complete current source/candidate
probe and decode. Compare actual decoded sample bytes and exact frame timing in
addition to the closed stream-copy container/payload contract. Bind the selected
provider/build/resource policy to the reviewed artifact. Keep one cooperative
session deadline and recheck current subjects/tools before transaction use.

Only successful current validation constructs the private token. Deserialized
review/receipt data cannot substitute for it. Saved evidence still denies native
qualification and source-removal authority. Replacement uses the existing
execution lock/journal with a distinct video action identity; legacy PNG and
exact-duplicate contracts retain their meanings. No sibling dependency, new
codec engine or second process runtime is introduced. Native property/recovery
qualification and original-disposal authority remain separately gated.

Five boundary cases are authored and unrun. No compiler, tests, format/schema
checks, dependency operations, provider/media execution or CI ran.
