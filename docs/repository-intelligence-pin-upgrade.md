# Repository Intelligence pin-upgrade handoff

This is a source-review candidate for OptiFlow's existing Pages publisher,
prepared on November 9, 2026. It does not establish deployment or production
acceptance. The parent work is
[organization Repository Intelligence #41](https://github.com/egohygiene/.github/issues/41);
the existing publication ownership comes from
[OptiFlow #28](https://github.com/egohygiene/optiflow/issues/28) and
[ADR-0001](decisions/ADR-0001-publication-stack.md).

## Exact source boundary

| Input | Immutable revision |
| --- | --- |

The candidate is the unreleased immutable Relay source selection in
[Relay draft #167](https://github.com/egohygiene/relay/pull/167). It brings the
shared repository route shell and portable navigation/evidence graph into the
existing `.site/producers/intelligence` output. OptiFlow's composer recursively
copies that complete bundle under `/intelligence/`; the organization site owns
only the fleet overview and links into repository-owned views.

The action keeps its existing output/work/report paths, exclusions, activity
window, depth limit, and complete-history requirement. No native collector,
provider capture, Observatory snapshot, comparison input, consumer alias, or
deployment-provenance integration is enabled. Source-backed views must retain
explicit unavailable states where evidence is absent. The ADR migration and
human-authority prerequisites documented in the
[migration map](decisions/MIGRATION-MAP.md) remain independent.

## Publication and recovery boundary

The existing Pages build and single protected deployer keep their events,
permissions, concurrency, timeouts, job dependencies, branch gates, environment,
artifact path, and retention. Product assets, composition code, site verifier,
and the unrelated release-workflow Relay pin are unchanged. This candidate
introduces no scheduling or deployment redesign.

Historical rollback reconstruction must retain the original OptiFlow revision,
Relay pin, generated bytes, evidence, and recorded environment constraints.
The new pin does not retroactively repair old bundles or create an accepted
rollback point. The existing reviewed-revert procedure in the
[publication guide](site-publication.md#rollback) still applies; retain the last
known-good artifact until the new candidate has separate acceptance evidence.

## Review evidence and next checkpoint

Source inspection confirmed that the candidate retains the producer files
required by the current composer: `index.html`, `styles.css`, `explorer.js`, and
`summary.json`. Its dashboard summary still declares
`egohygiene.repository-intelligence-dashboard/v3`, `schema_version: 1`.
This is contract inspection, not an executed OptiFlow composition.

Tests, dependency installation, builds, validators, CI, browser checks, provider
runs, deployment, live-route verification, and rollback rehearsal were deferred
at the maintainer's request. No Actions were dispatched or polled. A later
acceptance pass must bind the exact consumer/generator revisions to the composed
artifact, verify unrelated route preservation, inspect generated routes and
unavailable states, and record deployment and recovery evidence separately.

ADR not required: this consumes the existing isolated-producer architecture
without changing source authority, composition ownership, or deployment policy.
